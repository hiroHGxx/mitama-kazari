参加者へ期待結果や理想操作を先に見せない。結果は実施中に results.jsonl へ逐次保存する。 observed は事実だけを書き、interpretation は空のまま渡す（解釈は分析工程の持ち場）。
この run の参加者は人間ではない。AI（検品担当・結）が puppeteer-core（Chrome 実機バイナリ）で 初見の遊び手を代行する。表示・数値・時間・コードは direct な観察として扱えるが、 人間の初見の言語化・体感速度・実指の感触（スワイプ・safe-area・共有シート）は原理的に演じられない。 それらは各シナリオの「実施」欄に not-tested（実機のみ）と明記し、最後にまとめて実機へ回す。

0. 目的・範囲・前提

  • 対象: 『月蝕綺譚』の二次創作の道具「夜じたて」。ゲームではない。札絵を端末寸法に額装して写真に保存するまでを受け持つ。対象の姿は SPEC.md §7.7「閉じた姿ひとつに」＝1画面・状態はひとつ（開閉の仕掛けが無い）。
  • 対象ユーザー: 『月蝕綺譚』のファンで、推しの札絵を壁紙にしたい人。ショートカットやiOSの設定には詳しくない。29柱・里・深さ10段の語彙は知らない状態で開く。
  • 対象ジャーニー: 開く → 顕れを見る／飛ばす → 推しを選ぶ（列 or 名札） → 深さを選ぶ（タップ／なぞり） → 保存する → 壁紙にする手順を知る。
  • 対象外: 額装の幾何の数値そのもの（継ぎ目・蝕環・書き出しの重さ＝check-frame.js が既に担保）、台帳の一致（build-roster.js --check）、色・文字段・角丸の散らかり度（意匠＝金継ぎの持ち場）、実際の壁紙設定（この道具の外・SHORTCUT.md）。
  • 実施環境: このリポジトリを Node.js の観察スクリプトが Content-Type: text/html; charset=utf-8 付きで自動割当ポートに配信したもの。本番 origin（github.io）では実施しない——本番の localStorage（yo-jitate.pick）はオーナーの控えだから。ローカル origin は同時に「初見の状態」でもある。
  • 受入の正本: docs/SPEC.md（節番号で追跡）。既存の機械検査 scripts/check-layout.js は本 run の直前に単独で実行し、150項目すべて通ることを確認済み（baseline.md 参照）。この run はその検査が見ていない「初見の理解・迷い・回復」を見る。
実施順の逸脱について（明示）: 設定の execution.order は非破壊→可逆変更→不可逆の順。 本作の可逆変更は localStorage の1キー（yo-jitate.pick）に限られ、配信サーバーごと閉じれば消える。 唯一の不可逆・外部影響は「写真に保存」が実機で開く共有シート（navigator.share）。 ヘッドレスでは開かず永久に待つ性質のため、機械実施では3つの結末（AbortError／resolve／download）を差し替えて 「札（#tips）が出るか」だけを見る（C-8）。実際の共有シートの体験は C-9 として実機のみに回す。
観察する側の罠（DEVELOPMENT.md・check-layout.js から必読）
  • 開幕の1.2秒は入力が伏せられている。待たずに叩くと pointer-events:none をすり抜けて別の要素を叩き、「開かない」という嘘の落ち方をする。body.locked が消えるまで待ってから叩く（ready(page)）。緑が出たら、まず「本当に何かしたのか」を疑う。
  • ヘッドレス Chrome の screen.width は OS の画面を返す。端末寸法は #size= で上書きする。
  • navigator.share は解決も棄却もしない。永久に待つので、必ず差し替えてから叩く。
